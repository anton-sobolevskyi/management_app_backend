# Розгортання

Цей документ описує, де і як запустити проєкт у Docker, зокрема безкоштовно.

> **Про актуальність.** Безкоштовні тарифи змінюються часто (протягом 2026 року Koyeb вимкнув
> варіант без картки, Render змінив ліміти, Fly.io прибрав безкоштовний тариф для нових
> користувачів). Огляди в мережі суперечать один одному, а багато з них пишуть самі
> хостинги. Тому цифри нижче: орієнтир станом на жовтень 2026. Перед вибором відкрийте
> сторінку цін провайдера.

## Що потрібно застосунку

| Компонент          | Навіщо                                | Примітка                                                                                           |
| ------------------ | ------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Контейнер з Node   | сам API (образ з `Dockerfile`)        | порт з `PORT`, health: `GET /health`                                                               |
| PostgreSQL 16+     | дані                                  | потрібне розширення `pg_trgm` (міграція створює його сама)                                         |
| S3-сумісне сховище | вкладення й аватари                   | посилання на файли підписуються на адресу з `AWS_S3_ENDPOINT`, тож вона має бути доступна браузеру |
| SMTP               | листи скидання пароля й підтвердження | без `SMTP_URL` листи нікуди не йдуть (поза production вони лише в логах)                           |
| HTTPS-домен        | cookie з refresh-токеном, CORS        | у production обов'язково                                                                           |

Безкоштовного «усе в одному місці» без картки, без «засинання» і з Postgres практично немає.
Тому зазвичай комбінують три-чотири сервіси.

## Що обрати для навчання

- **Варіант A: одна VM і compose** (рекомендую, якщо мета розібратися). Файли вже в репозиторії:
  `docker-compose.prod.yml`, `deploy/Caddyfile`, `.env.prod.example`. Зовнішніми лишаються
  лише сховище (R2 або B2) і SMTP.
- **Варіант B: Cloud Run + Neon + R2.** Менше адміністрування, але потрібна картка і треба
  стежити за квотою.
- **Варіант C: нічого не публікувати.** Для навчання часто досить `docker compose` локально.
  Перевірте, що все працює, а на публічний сервер переходьте, коли з'явиться фронтенд.

## Варіант A: покрокове розгортання на VM

1. Створіть VM з Linux, відкрийте порти 22, 80 і 443, налаштуйте вхід лише за SSH-ключем.
2. Встановіть Docker Engine і плагін Compose.
3. Додайте A-запис домену на IP сервера (Caddy сам отримає HTTPS-сертифікат).
4. Клонуйте репозиторій та створіть конфіг:
   ```bash
   cp .env.prod.example .env.prod
   openssl rand -base64 48   # вставте в JWT_ACCESS_SECRET
   nano .env.prod            # DOMAIN, паролі, FRONTEND_URL, S3, SMTP
   ```
5. Запустіть:
   ```bash
   docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
   ```
   Міграції застосовуються під час старту контейнера.
6. Перевірте: `curl https://ВАШ_ДОМЕН/health` має відповісти `{"status":"ok","database":"up"}`.
7. Оновлення: `git pull` і повторіть команду з кроку 5. Логи: `docker compose -f docker-compose.prod.yml logs -f app`.
8. **Резервні копії:** без них це не production. Мінімум раз на добу:
   ```bash
   docker compose -f docker-compose.prod.yml exec -T postgres \
     pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" | gzip > backup-$(date +%F).sql.gz
   ```
   Копії зберігайте поза сервером і хоч раз перевірте відновлення.

> Файли compose і Caddy я перевіряв лише на коректність YAML. У моєму середовищі не було
> Docker, тож повний запуск перевірте самі й, якщо щось не так, виправте.

## Особливості цього проєкту на різних платформах

- **Neon.** Для застосунку використовуйте _pooled_-рядок підключення, а для міграцій
  _direct_ (`RUN_MIGRATIONS=false`, окремо `npx prisma migrate deploy` з direct-адресою).
  Після простою перший запит повільніший (база прокидається).
- **Cloud Run та інші платформи з кількома копіями.** Також `RUN_MIGRATIONS=false` і
  міграції окремим кроком. Платформа сама задає `PORT`. Ліміти запитів зараз у пам'яті
  кожного інстансу (див. «Security notes» у README).
- **Сховище.** Для R2: `AWS_REGION=auto`, `AWS_S3_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com`.
  Для B2: регіон на кшталт `us-west-004`, endpoint `https://s3.<регіон>.backblazeb2.com`.
  MinIO в тому ж compose для production не підходить: підписані посилання вказували б на
  внутрішню адресу контейнера, недоступну браузеру. Якщо фронтенд завантажує файли
  через `fetch`, на бакеті потрібне налаштування CORS.
- **Різні домени фронтенду й API.** `COOKIE_SAME_SITE=none` (лише HTTPS) і точний
  `FRONTEND_URL`.
- **Листи.** Фронтенд має реалізувати сторінки `/reset-password` і `/verify-email`, які
  беруть `token` із query-рядка (деталі в README, розділ «Account recovery»).

## Перед публікацією

- [ ] `JWT_ACCESS_SECRET`: довгий випадковий рядок; `.env.prod` не в git
- [ ] `FRONTEND_URL` точно збігається з origin фронтенду
- [ ] порт Postgres не опубліковано назовні (у `docker-compose.prod.yml` він закритий)
- [ ] працюють резервні копії, і відновлення перевірено
- [ ] налаштовано SMTP, а листи скидання пароля реально доходять
- [ ] увімкнено оновлення ОС і Docker-образів, закрито зайві порти файрволом
